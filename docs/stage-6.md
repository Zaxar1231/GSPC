## Как устроено

- `rustdroid_input::keymap::Keymap` — чистая логика: события хоста (`HostEvent`: клавиша по
  имени, движение мыши, курсор, колесо) → касания (`TouchOp`: Down/Move/Up по слотам 2–9).
  Время передаётся снаружи, жесты со временем (свайп, щипок, макрос, повтор) движок планирует
  сам, хост вызывает `tick` не позже `next_deadline`.
- `crates/app/src/controls.rs` — общий для UI-потока и потока `keymap` движок: события окна
  обрабатываются сразу (без очереди), поток `keymap` выполняет жесты по времени, раз в секунду
  спрашивает у агента активное приложение и включает захват мыши для прицела.
- `rustdroid_input::editor::Editor` — редактор профиля, тоже чистая логика с тестами; метки
  (`present::run::Markers`) рисует композитор прямо в буфер загрузки кадра.

## Редактор (F12)

| Действие | Что делает |
|---|---|
| F12 | открыть редактор активного профиля (или нового для текущей игры); повторно — закрыть и сохранить |
| мышь на контроле | выбрать и перетащить |
| клик по пустому месту, затем клавиша | новый `tap` на этой клавише |
| клавиша при выбранном контроле | переназначить (у джойстика — в файле профиля) |
| Delete / Escape | удалить выбранный / снять выбор |
| колесо над джойстиком или скиллом | радиус |

Пока редактор открыт, игра ввод не получает. Профиль сохраняется в свой файл; новый — в
`--profiles DIR/<package>.rdprofile`, иначе в файл `--profile` (его может ещё не быть), иначе в
`rustdroid.rdprofile` в текущей папке.
