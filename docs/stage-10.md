## 10.1: что нужно сохранить (по коду `crates/vmm/src/vm.rs`)

| Часть | Где | Что сохранять |
|---|---|---|
| vCPU | `whpx` (WHPX-раздел) | регистры, MSR, состояние APIC, XSAVE |
| Прерывания и таймеры | `Serial16550`, `CmosRtc`, `IoApic`, PCI | регистры устройств, маршрутизация |
| Память | RAM раздела WHPX | весь диапазон RAM гостя |
| virtio-blk | `devices/src/blk.rs`, `disk.rs` | позиция очереди, CoW-оверлей уже на диске |
| virtio-console | `devices/src/console.rs` | буферы ввода и вывода |
| virtio-vsock и службы | `devices/src/vsock.rs`, `agent.rs`, `cf_services.rs` | открытые соединения (их проще сбросить) |
| virtio-net | `devices/src/net` | таблица NAT: TCP-соединения при восстановлении не сохраняем |
| virtio-input | `devices/src/input.rs` | состояние касаний (слоты) |
| virtio-gpu и gfxstream | `crates/gpu`, `crates/gfxstream` | см. 10.5 |

## Проблемные места

- **gfxstream.** Состояние GPU живёт в процессе хоста и не сериализуется. Запасной путь:
  сохранять только гостевое состояние и пересоздавать GPU-контекст, но тогда драйвер гостя
  должен это пережить. Нужен эксперимент на железе.
- **Сеть.** TCP-соединения при восстановлении не сохраняются: гость увидит разрыв и
  переподключится.
- **Касания.** Слоты, которые были нажаты на момент снимка, надо отпустить при восстановлении
  (`release_all`, см. `rustdroid-input`).
