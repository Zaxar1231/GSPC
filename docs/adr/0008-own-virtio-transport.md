# ADR 0008: свой транспорт virtio-pci, virtqueue и формат copy-on-write

- Статус: принято
- Дата: 2026-11-08

## Контекст

`virtio-queue` из rust-vmm требует трейтов `vm-memory`, от которых мы отказались (ADR 0007).
Для дисков нужен мгновенный сброс инстанса и разделы Android из нескольких файлов.

## Решение

- **virtqueue:** своя split-очередь (`crates/virtio/src/queue.rs`):
  - `EVENT_IDX` и indirect-дескрипторы;
  - защита от циклов в цепочках;
  - переиспользуемый буфер цепочки, без аллокаций в горячем пути.
- **virtio-pci modern:**
  - фиксированная раскладка BAR0, notify с шагом 4 байта;
  - каждый notify-адрес регистрируется как doorbell WHPX;
  - прерывания — только MSI-X, без INTx.
- **Синхронизация:** функция PCI под `Mutex` без конкуренции: vCPU трогает её только при
  настройке, а очереди обслуживает один worker. Для virtio-gpu (этап 4) состояние очередей будет
  разделено без блокировок.
- **Copy-on-write (`RDCOWv1`):**
  - заголовок 4 КиБ, таблица `u64` на кластер 64 КиБ, данные дописываются в конец;
  - базовый образ не меняется, сброс инстанса — удаление оверлея.
- **Составной диск:** таблица GPT (защитный MBR, основная и резервная копии с CRC32)
  синтезируется в памяти, данные читаются из образов разделов без копирования.

## Последствия

- Не зависим от rust-vmm в горячих путях virtio.
- Данные virtio-blk пока копируются через промежуточный буфер. Прямое копирование в гостевую
  память — оптимизация следующих этапов, если её покажут замеры.
