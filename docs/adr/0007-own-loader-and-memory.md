# ADR 0007: свои загрузчик ядра и слой гостевой памяти

- Статус: принято
- Дата: 2026-11-08

## Контекст

В плане стояли крейты rust-vmm `linux-loader` и `vm-memory`. Оба исторически ориентированы на
Linux/KVM: Windows-бэкенд `vm-memory` нестабилен, `linux-loader` тянет его за собой.

## Решение

- **Гостевая память** — свой `GuestRam` (`crates/vmm/src/memory.rs`): один блок `VirtualAlloc`
  (опционально `MEM_LARGE_PAGES`), prefault, участки GPA вокруг MMIO-дыры, копирование через
  проверенные сырые указатели.
- **Загрузчик** — свой разбор bzImage и заполнение `boot_params` по boot protocol 2.12+
  (`crates/vmm/src/loader.rs`), около 300 строк с тестами.
- Из rust-vmm берём `vm-superio` (16550). `virtio-queue` будет на этапе 2, он не зависит от
  бэкенда памяти через трейты, которые мы реализуем сами.

## Последствия

- Полный контроль над выделением памяти: большие страницы сейчас, file-backed copy-on-write для
  быстрых снапшотов (этап 10) позже.
- Меньше зависимостей в горячих путях.
- Поддержку новых версий boot protocol проверяем сами (тесты на синтетическом bzImage).
